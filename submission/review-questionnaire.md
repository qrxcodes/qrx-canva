# Answers for Canva's review questionnaire

Canva sends its questionnaire in the review ticket after submission, and its exact questions aren't published. These
answers cover what it and the submission checklist ask about. Keep them factual: describe only what is in place on
the day of submission, and update the moderation answer if the owner adds an image check first.

## The app

**What does the app do?**
It makes an art QR code from a picture description and a link, and adds the finished image to the user's design. The
user connects a QRX account, types what the picture should show and the web address the code should open (a blank
field is filled with the example shown in it), optionally adds a logo for the centre of the code and picks a style,
and waits about a minute while QRX makes the code. On a plan with Wi-Fi codes, the code can join a Wi-Fi network
instead of opening a link.

**Who is it for?**
People making printed or on-screen designs that carry a QR code: posters, menus, flyers, packaging, event signage and
slides, where a plain black-and-white square would clash with the design.

**How is it different from existing apps and Canva's own QR code features?**
- Every code is decoded before it is delivered. QRX's pipeline reads the finished image with a QR decoder and only
  returns it when it opens the right link; general image models often produce art codes that don't scan.
- Each code encodes its own hosted short link (`https://qrx.to/<id>`) rather than the user's URL. The short link keeps
  the pattern sparse, which helps it scan inside a picture, and it can be redirected.
- On a paid plan, the user can change where a code points after it has been printed, without changing the design.
- The codes live in the user's QRX account, so the same code is available on qrx.codes and through QRX's API and other
  integrations.

**What permissions does it use, and why?**
- `canva:asset:private:write`: to upload the finished PNG to the user's uploads.
- `canva:design:content:write`: to place the image on the page.

It asks for nothing else and reads nothing from the design. A logo comes from a file the user chooses in the panel
(the App UI Kit's `FileInput`).

## Authentication and data

**How do users sign in?**
OAuth 2.0 authorisation code flow with PKCE through Canva's OAuth support (`auth.initOauth`). The identity provider is
QRX's Clerk instance. Canva stores and refreshes the tokens; the app keeps no tokens or credentials itself. Sign-in and
sign-up happen in the authorisation tab, never in the panel. Disconnecting calls `deauthorize`, and Canva's revocation
URL is configured so removing the app revokes the tokens.

**What data does the app send, and where?**
To the QRX API (qrx.codes, HTTPS only): the picture description, the link (or, for a Wi-Fi code, the network name,
security type and password), the chosen style, the logo image if the user chooses one (prepared in the panel as a PNG
of at most 1024 px), the QRX access token, and the Canva user token (a short-lived JWT the API uses to verify that
requests come from this app). QRX stores the description, link or network name, style, logo and finished image in the
user's QRX account so they appear in the user's gallery. The Wi-Fi password is printed into the code and isn't stored
with it. Nothing
is sent to any other service from the app. The app reads nothing from the design.

**Do you sell or share user data, or use it for advertising?**
No. There are no ads in the app, and Canva data is not used to contact users.

**Privacy policy:** https://qrx.codes/privacy. **Terms:** https://qrx.codes/terms.

## Payments

**Does the app take payments or show prices?**
No. Nothing is sold in the app and no prices are shown. QRX has a free account and paid plans, managed on qrx.codes.
Where `getPlatformInfo().canAcceptPayments` is true, the panel mentions that changing a code's link is available on a
paid plan and, when the daily allowance is used up, offers a "See plans on qrx.codes" button opened with
`requestOpenExternalUrl`. Where it is false, neither appears; the daily-limit message says to open qrx.codes in a
browser, without a link.

## AI and generated content

**Does the app use generative AI?**
Yes. The QR code image is generated by an image model that QRX runs on GPU servers it operates through a cloud GPU
provider. The user's description is the prompt; QRX adds the QR pattern for the user's short link as a control input.
No third-party AI API receives the prompt. *(Owner: confirm this matches the production pipeline on the day of
submission, and whether to name the model.)*

**How is AI-generated content disclosed?**
Every image is uploaded with `aiDisclosure: "app_generated"`. The listing description says the images are made with
AI. Nothing in the app suggests the images are made by a person.

**What moderation is in place?**
- **Prompts are word-filtered.** The app checks the description with the `obscenity` English word list (the same
  filter Canva's generative AI template uses) before sending it, and the QRX API runs the same filter on every
  request and refuses matching prompts.
- **There is no check of the finished image for unsafe content yet.** The only check on the output is the scan check
  (the image is decoded to confirm the QR code opens the right link). The production image model doesn't apply a
  negative prompt. QRX is deciding whether to add an image safety check; until one is live, the word filter is the
  only content safeguard.
- **Logos are the user's own images.** A chosen logo is placed in the centre of the code as given; it isn't checked
  for content.
- **Reporting.** Under each finished code, the panel links to Canva's report form ("Something not right with an image?
  Report it"). Users can also contact QRX through https://qrx.codes/support.

**Can the app generate the content Canva's terms prohibit (nudity, political or election content, medical, legal or
financial advice, code, malware)?**
The app only makes pictures, so it produces no advice, contracts or code. For images, the word filter blocks explicit
and offensive terms in the description; it does not detect political subjects, and there is no output check, as
above.

## Reliability

**How does the app handle long waits and errors?**
Codes take about a minute. The app shows a progress bar (not a spinner) paced to that time, keeps polling with server
long-polls of 25 seconds, and stops waiting after five minutes; the code still appears in "Recent codes". Retrying a
create after a network failure reuses an idempotency key, so a retry can't make or charge a second code. Errors have
specific messages (daily allowance used, too many requests, account disconnected, server trouble, network) with a
next step, plus a catch-all.

**Where is the backend hosted?**
The QRX API runs on Microsoft Azure Container Apps; image generation runs on dedicated cloud GPU workers. It's the
same API that serves qrx.codes.
